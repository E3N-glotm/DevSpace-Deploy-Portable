# DevSpace Portable dev88 validation — 2026-09-17

## Trigger

Remote Agent local SSH install/update failed on root-only Linux servers with:

`Refusing to run the DevSpace Agent service as root. Re-run with --user <ordinary-linux-user>.`

The failure was deterministic. `install.sh` defaulted `RUN_USER` from the remote shell identity. When SSH connected as `root`, it attempted the historical `ubuntu` fallback and rejected the install if that account did not exist.

## dev88 change

- Add an explicit installer capability: `--allow-root-service`.
- Root remains denied by default. Without the explicit flag, a root invocation still uses the historical `ubuntu` fallback when available, otherwise fails closed.
- The Portable local SSH installer appends `--user root --allow-root-service` only when the configured SSH username itself is exactly `root`.
- Interactive SSH install/update passes the current SSH editor username into the offline installer builder.
- Background SSH auto-repair passes the persisted SSH profile username into the same builder.
- Non-root SSH users do not receive the root-service flag and keep the existing behavior unchanged.
- Systemd/background startup, ownership fixes, Scoped restrictions, Full Access behavior and the Agent's own path/command guards are otherwise unchanged.

## Security boundary

This is an explicit opt-in, not a global relaxation. Merely running the installer under sudo/root does not enable a root Agent. The opt-in is generated by the Portable SSH workflow only when the operator configured the remote login identity as `root`.

## Validation gates

1. `install.sh` Bash syntax validation.
2. `setup/test-remote-agent-ssh-rescue.mjs` root/non-root SSH generation contract.
3. `setup/test-linux-agent-contract.mjs` installer root opt-in/default-deny contract after canonical package rebuild.
4. Native UI build/self-test, including generated root SSH install command.
5. Source-tree/manifest and D-live deployment gates before declaring dev88 live.
