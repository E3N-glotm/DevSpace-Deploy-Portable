# 模型提供商与 Agent 工作台

DevSpace 1.1.68 可以用已配置的单模型或模型组运行持久任务。任务可从 Windows 控制中心启动，也可由 ChatGPT 经 DevSpace MCP 委派。

## 添加模型

1. 打开「模型提供商」，选择提供商和 API 接口，填写 Base URL、模型标识，以及提供商要求的 API Key。
2. 按任务需要选择角色。Worker 负责执行，Reviewer 负责独立审查，Planner 负责规划。默认单模型列表显示已启用的 Worker。
3. 保存后开启「允许调用」。用页面的检测功能核对端点、工具调用或思考配置。检测会发起请求，云端提供商可能计费。
4. 根据后端实际支持的容量设置上下文窗口与最大输出。上下文窗口字段用于 DevSpace 管理任务历史，物理容量由模型服务和所选模型标识决定。思考档位是否被执行取决于后端，可查看检测返回的思考输出和 Token 证据。

## 选择调度方式

在「模型提供商 → 全局模型调度」选择模式。这项设置同时用于 MCP 委派任务和工作台新建任务。

| 模式 | 执行方式 |
| --- | --- |
| 自动 | 一般任务走单模型。要求独立复核时需配置默认模型组。仅有并行子任务且未配置默认组时，可以回到单模型 |
| 单模型 | 优先使用指定的默认 Worker。未指定时选择可用 Worker |
| 模型组 | 使用默认模型组。通过「创建 / 管理模型组」配置成员、角色和审查要求 |

工作台的「本次模型调度」可跟随全局，也可为这次任务选择其他模型或组。需要复核的任务应设置明确的验收标准，模型组需有可用的独立审查成员。保存过的默认 Worker 无法调用时，在「全局模型调度」更换该 Worker 或改回自动选择。

## 发起、验收和恢复任务

在「Agent 工作台 → 新建任务」填写工作区路径、任务目标与验收条件，再启动任务。例如，可要求模型只读检查某个模块，并在结果中列出文件路径、行号和复核依据。

通过 MCP 发起时，先用 `open_workspace` 打开工作区。使用 `agent_task_start` 创建任务，用 `agent_task_status` 查看状态和结果，用 `agent_task_events` 查看工具记录和协作事件。建议传递清楚的读写要求、目标文件和验收条件。

默认继承 DevSpace 的「文件访问」「操作权限」和功能开关。桌面任务可展开权限设置关闭单项。MCP 委派的严格只读任务可将 `allowWrites`、`allowShell`、`allowComputer`、`allowMemory`、`allowPlugins` 全设为 `false`。子任务的操作范围由上游授权和 DevSpace 当前权限共同决定。

| 状态或操作 | 处理 |
| --- | --- |
| 运行中 | 查看任务步骤、成员输出、工具记录与用量。上游对话可继续读取状态 |
| 等待验收 | 核对结果与工具证据，再人工验收。普通 MCP 单模型任务在成功交付后可自动归档 |
| 已暂停 | 查看原因。若上次工具执行结果未知，先核对工作区或桌面实际状态，再确认恢复 |
| 取消 | 当前模型请求会终止，任务无法直接恢复。已执行的文件修改需要另行处理 |

MCP 侧的任务控制按创建任务的对话隔离。若需处理旧版遗留任务或其他对话的任务，可在本机工作台操作。查看历史结果时，可先核对原始工具记录，再使用模型结论。
