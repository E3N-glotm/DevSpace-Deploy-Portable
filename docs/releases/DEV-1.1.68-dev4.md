# DevSpace Portable 1.1.68 dev4 — 强制模型工作流与按模型禁用

本开发版在“服务与运行权限”中新增“强制模型工作流”，在“模型提供商”的每个已保存配置中新增“允许调用”。两个开关都由本体执行，不依赖插件。

## 强制模型工作流

- 默认关闭：上游 ChatGPT、Open WebUI 等客户端自主选择是否委派 Worker。
- 启用前要求至少一个允许调用、具备模型 ID、无需 Electron API Key 解密的 Chat Completions Worker，否则拒绝开启。
- 启用后服务端在 MCP HTTP 的 tools/call 入口统一检查。允许先打开本地工作区、查询 Worker、委派任务、查看状态与结果，以及安全诊断、取消任务和续轮控制；普通工作区与插件任务工具则必须先完成 Worker 委派，使用 model_task_result 获取 completed 结果。
- 失败、正在运行的 Worker、没有启用模型、配置损坏以及未经过委派的调用一律阻断，不会在后台静默退回上游模型直接执行。
- 授权绑定 MCP 会话、可识别的 conversation scope、工作区、策略版本和模型配置修订，最长 5 分钟。开启／关闭策略以及修改模型会撤销旧授权。
- 强制模式中拒绝批量 JSON-RPC tools/call，避免绕过单次调用检查；仍然保留必要的诊断、配置与撤销控制。
- 策略保存于 Portable 用户数据目录 data/config/model-workflow.json；服务端按请求读取，正常无需重启。

## 允许调用

- 旧配置默认保持允许调用，不会在升级后自动禁用已有模型。
- 禁用后模型不再出现在可用 Worker 列表中；显式委派、桌面连接测试与 Function Calling 探测均拒绝新请求。
- 运行中的 Worker 每一步复查配置，HTTP 等待期间每 500ms 检查是否禁用并尝试取消。
- 禁用不会删除模型配置、加密凭据或历史调用统计，并且会撤销该模型的短期工作流授权。

## 适用范围与限制

- 强制门禁只能保证经过 DevSpace MCP 的任务工具不会直接绕过 Worker；不能修改 ChatGPT 本身的模型选择，也不能禁止上游在完全不调用 DevSpace 的情况下直接回复。
- 当前内置 Worker 仅支持本地工作区的读取、搜索和精确编辑。强制模式下不支持的远程工作区不会被虚构为成功，远程任务将被明确阻断。
- 已完成的委派可授权当前会话及工作区最长 5 分钟。该机制不能可靠识别所有客户端的每条新用户消息；如要每条新消息强制重新委派，需要上游提供可信任的轮次边界信号。
- 不修改原有 Shell、Git、删除、凭据、远程权限和自动续轮逻辑。现有权限和人工确认仍独立生效。

## 验收

- 验证默认行为、强制阻断、无 Worker、运行中与失败任务、跨会话隔离、授权过期、模型禁用、策略切换、模型编辑失效及批量请求拒绝。
- 使用 E 盘隔离工作区与假推理服务进行真实 OAuth + MCP HTTP 测试：未委派阻断 → Worker 成功完成 → 读取结果放行 → 禁用模型再阻断 → 关闭强制模式后恢复上游自主执行。
- 完整 Portable 回归继续覆盖模型配置／统计、工作区、权限、自动续轮、SSH Agent、更新器和生产依赖安全审计。
