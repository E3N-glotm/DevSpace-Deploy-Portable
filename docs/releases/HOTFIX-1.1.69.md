# DevSpace Portable 1.1.69 正式版

2026-11-20 更新了本版本的安装包与 blockmap，版本号保持 1.1.69。

## 更新机制优化

- 主更新路径仍为通用 blockmap：客户端从完整目标索引计算差异，下载缺失块，仅暂存并事务替换变化文件；不依赖为特定旧版本预先生成的小增量 ZIP。
- 初次分析使用有限并发计算真实哈希；后续分析复用校验缓存，文件大小、时间或身份变化时重新计算。缓存只加速差异分析，安装前校验变更计划和本地状态，安装后仍对全部目标文件执行 SHA-256 内容校验，失败则回滚并使缓存失效。
- 未变化文件不再全量重组和搬运，暂存文件不再逐个强制刷盘；复用测速中的索引数据，并合并邻近小块、并发下载缺失范围。
- 控制中心分别显示索引下载、本地分析、缺失块下载和变化文件准备进度。
- 保留已有完整暂存模式、完整包回退和历史引导更新包的兼容性。已有旧更新器在首次升级时仍执行自身旧逻辑；安装本次修订包后，后续更新使用新机制。

适用于 Windows x64。本版修复模型已在工作、Agent 协作页面却没有任务，以及上游单模型参数绕过全局分组设置的问题。

## 统一任务记录

- `model_delegate_task` 兼容入口与 `agent_task_start` 原生入口统一创建 Agent Runtime 任务。即使旧客户端传入 `useSpecifiedModel=true`，新任务也会进入协作列表，保存状态、过程和结果。
- 新兼容调用返回可见的 `agent_` 任务 ID，并保留旧客户端使用的 `taskId`、`answer`、Token 用量、费用和工具证据字段。状态查询与取消仍遵守原有的任务归属和权限检查。

## 全局模型调度

- 通过 MCP 派发任务时，全局“单模型”或“分组”设置优先于调用方的 `modelId`、`groupId`、`routeMode` 和兼容模型参数。全局选择分组后，上游不能再通过单模型参数将任务悄悄改成单模型。
- 全局“自动”模式继续允许按任务选择模型或模型组；本机工作台中由用户手动选择的单次任务设置仍有效。
- 调度在任务创建时确定，更改全局设置不会自动改组、重启或重放正在运行的任务。本次修复没有增加模型回复长度、执行步数或等待时限。

## 验证与更新

已通过 Agent Runtime、Worker 与工作流权限回归，以及两种工具模式下的真实 OAuth、MCP 和工作台 HTTP 隔离测试。测试覆盖兼容参数、工作台可见性、全局设置优先级、独立审查、写入互斥和跨会话取消保护。

GitHub Release 提供完整 ZIP、`.blockmap`、旧版本兼容更新包、更新清单及 SHA-256 校验文件，并标记为 Latest。通过应用更新入口安装时，保留已有配置和 Agent 任务等持久数据。
