# DevSpace Portable 1.1.68 dev6 — 远程工作区强制门禁修复与禁用模型 UI 修复

本版在 dev5 异步委派基础上修复三处 DevSpace 自身问题，不涉及远端推理服务、SSH 隧道和模型路由。

## 强制 Worker 与远程工作区

- 强制模型工作流只要求**本地工作区**事先显式提交允许调用的 Worker 任务；远程 Agent 工作区仍由 GPT 主代理直接执行其获准的 MCP 操作。
- 远程身份由 DevSpace 服务端工作区注册表解析，不接受用户调用时自行声明的远程标志；不存在的 workspaceId 不能绕过本地门禁。
- 远程工作区不会被错误标为 Worker 已执行。当前 Worker 后端仍仅支持 Windows 本地工作区，日后支持远程委派时需单独设计授权与执行协议。
- 保留所有已有的远程 Agent 权限规则、人工确认、路径限制和审核，不因这项豁免而提升权限。

## 强制开关的动态状态

- 不再在 MCP 会话建立时缓存“强制模式当前开/关”或要求同步等待完成的旧操作指令；静态提示改为要求通过 model_worker_list 查询实时策略。
- 具体工具门禁仍按调用时的用户设置动态判定，关闭开关无需重启 MCP。不同策略修订下的旧 Worker 授权不复用。
- 通过同一 OAuth/MCP 客户端连接连续测试 开启 → 关闭 → 开启 → 关闭，检查状态报告与本地工具实际阻断效果。
- 现场只读核查时，D 盘 model-workflow.json 已为 enabled=false；没有证据证明曾自动翻转，本次修复重点是客户端缓存过期指令导致的误判风险。

## 模型提供商 UI

- “允许调用”关闭的模型仍可被选中、查看调用统计、编辑并保存配置；选中或保存禁用模型时不再自动请求 /models，避免显示 MODEL_CALLS_DISABLED 红色异常。
- 禁用时模型列表、测试连接和 Function Calling 操作按钮不可用；重新开启“允许调用”后恢复。
- 使用选中模型 ID 与请求代次双重校验，过期的异步模型列表响应或错误不再覆盖当前页面状态。
- 后端对禁用模型的调用拒绝仍保留，防止绕过 UI 直接调用被禁用的模型。

## 验收范围

- 新增远程工作区仅按注册表身份豁免的单元回归，保留本地工作区严格强制门禁。
- 新增模型禁用 UI 保护回归和同 MCP 会话动态策略切换测试。
- 本地构建与发行包回归，不触碰 D 盘正式安装、真实 OAuth Token 或远程模型服务。
