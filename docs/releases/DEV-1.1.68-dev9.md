# DevSpace Portable 1.1.68 dev9 — 多网卡 Agent LAN 网关

## 故障与设计

双网卡 Windows 控制端原先只支持一个 `agent-network.json.bindHost`。已有 5090 Agent 使用有线 IP `192.168.219.14:7677`，向需要 WLAN 2 (`192.168.221.238`) 才能访问的 `100.200.199.25` 添加 LAN Agent 时，`agent-network-prepare` 会拒绝切换唯一绑定地址。Electron 仅显示管理操作退出码 1，隐藏了经过脱敏后也可以安全展示的具体错误类型。

## 变更

- 新增 `bindHosts`（1–8 个明确指定的 RFC1918 IPv4 地址）。保留原 `bindHost` 字段作为首地址，现有单地址配置自动向后兼容；从不擅自把单网卡绑定改成 `0.0.0.0`，也不允许通配地址和指定地址混用。
- `agent-network-prepare` 使用 Windows 实际路由得到源 IP：新地址只追加到 `bindHosts`，不替换此前地址；原目标重复配置不再触发重复重启。新增网卡需要一次受控的本地 MCP 重启，不影响独立的 Linux 训练和 Qwen 进程。
- Agent-only LAN 网关在**相同端口**分别绑定每个指定 IPv4。网关保持仅暴露 `/agent/v1/devspace-agent.py`、`/agent/v1/install.sh` 和 `/agent/v1/connect` WebSocket；`/mcp`、OAuth 及其他路径不可通过此入口访问。
- 手动登记或网络切换时校验目标 LAN Agent URL 的 IP **和**端口确实属于已配置的网关监听集合，避免只检查端口而错误指向未监听的网卡地址。
- 若配置中的次要网卡暂时拔出或不可用（`EADDRNOTAVAIL`），其他可用网卡仍能启动；端口占用等非网络接口缺失错误不会被忽略。服务关闭时逐个关闭所有监听实例。
- 修复 Agent LAN 网关关闭流程中与活跃 WebSocket 的等待顺序：先启动所有监听器关闭，再同时关闭共享的 Agent 会话管理器，避免受控重启在 WebSocket 仍连接时等待死锁。
- 远程服务器页面显示已配置的监听地址、端口以及新增地址需重启本地 MCP 的提示；管理器输出固定、脱敏的网络错误码，Electron 将其解释成可操作的中文提示，不传递含凭据的原始 stderr。

## 测试与兼容性

- RFC1918、单地址旧配置、多地址追加/去重、通配排他、最多 8 地址、固定端口等校验；用真实 Windows 有线和 WLAN 2 接口验证同端口双监听、静态安装资源与 `/mcp`/OAuth 404，模拟副网卡离线后有线继续服务。
- 独立 E 盘配置实测 `100.200.199.25` 被映射到 `http://192.168.221.238:7677`；`172.39.60.14:55801` 仍映射到 `http://192.168.219.14:7677`；重复添加不会再次要求重启。
- 未修改 D 盘正式安装、现有 Windows 网络路由或防火墙；未重启已在线的 5090 Agent 或远程训练。覆盖正式安装后本地 MCP 需要一次明确的服务重启；远端必须能够反向访问所选的 Windows IPv4 与 7677 端口，才能完成新的 Agent 连接。
